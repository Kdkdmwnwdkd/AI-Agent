## 一、项目是什么（一句话定位）

**玄枵** 是 [AAswordman/Operit](https://github.com/AAswordman/Operit) 的**二改版**（Fork），跑在 Android 上的开源 AI Agent 平台。本质：**LLM + 200 多个工具 → 真实操作手机 / 终端(Ubuntu via PRoot) / 浏览器 / 文件**。约 46 万行 Kotlin，仅 ARM64，API 26+。

**二改版新增能力**（README 已声明）：SystemPrompt 中英合并、ModelRouter、工具调用链路追踪、三层记忆、敏感操作强制确认、清除双模式代码。

**关键认知**（用户反复强调）：
1. 聊天能力 和 Agent/代码/控手机能力是**并列**的，不是替代关系。聊天、语音(STT/TTS)、角色卡、记忆、模型接入都**不能动**。
2. 有些"看起来不规范的写法"是**有意留下的设计**，改之前必须判断"这是 bug 还是特色"。
3. 有**技能市场/商城**：外部开发者照着 `docs/doc-src/package-dev/*.md` 和 `examples/types/*.d.ts` 写脚本包，发布到市场供用户安装。**这些文档和 `.d.ts` 是对外契约，JS 接口是留给技能作者的，不能当"死代码"删。**

## 六、技术备忘

- **SAF 自选模型**：`LocalModelFileStore.resolveToFilePath()` 记住真实路径，`directPathOf()` 只认 `externalstorage` authority。native 层 `LlamaSession.create(pathModel)` 只接受真实路径。这就是不能简单换 `ACTION_GET_CONTENT` 的原因（第三方文件管理器 URI 无法还原路径）。
- **gh-proxy 下载**：`https://gh-proxy.com/https://api.github.com/repos/{owner}/{repo}/actions/artifacts/{id}/zip`，**不带 Authorization 头**（带了反而 403）。
- **APK v2 验签**：Signing Block 内线性搜 X.509 DER，判据 `blob[8]==0xA0 && blob[9]==0x03 && blob[10]==0x02 && blob[11]==0x01`。
- 工具参数名 schema 一致性：`SystemToolPrompts.kt`/`SystemToolPromptsInternal.kt` 声明 → `core/tools/defaultTool/*` 实现读取 → `JsTools.kt`/`assets/js/*`/`packages/*` JS 封装 → `examples/types/*.d.ts` 类型契约。改一处要四层同步（见 `docs/doc-src/architecture/DEFAULT_TOOLS_ARCH.md`）。

### 问题

`.github/workflows/pr-check.yml` 的 304-310 与 470-476 行有一组命令：

```yaml
- name: Initialize terminal submodule
  shell: bash
  run: |
    set -euo pipefail
    git submodule sync -- terminal
    git submodule update --init --recursive --depth 1 terminal
    git submodule status -- terminal
```

但 `.gitmodules` 里**只有** `tools/hotbuild/OperitNightlyRelease` 一条，**没有 terminal**。

### 排查结论：无害，保持原样

**1. 上游原生就有这 4 行**

`AAswordman/Operit`（`dbf7191`）的 `pr-check.yml:291-297` 和 `437-443` 存在**完全一致**的命令组，本仓库的行号只是整体偏移。→ **不是二改引入**，是上游历史遗留（`terminal` 早期疑为独立子模块，后来内联进主仓、`.gitmodules` 条目删除，但这几行没清理）。

**2. `terminal/` 是普通目录，不是子模块**

```
$ git ls-files terminal | wc -l                       → 68
$ git ls-files -s terminal | awk '$1=="160000"' | wc -l → 0
```

68 个文件**全部** `mode 100644`，**零个 `160000` gitlink**。

**3. 实测退出码：全为 0**

用临时仓库复现（含 `.gitmodules`、`set -euo pipefail` 等价条件）：

| 场景 | `sync` | `update` | `status` |
|---|---|---|---|
| 无 `.gitmodules`，terminal 为普通目录 | 0 | 0 | 0 |
| **有 `.gitmodules`（照抄本仓库），terminal 为普通目录** | **0** | **0** | **0** |
| 同上 + detached HEAD（模拟 `checkout github.sha`） | 0 | 0 | 0 |
| terminal 目录**完全不被 git 跟踪** | 1 | 1 | 1 |

前三种（**本仓库属于第三种**）全部退出码 0 —— git 能用 pathspec 解析到 `terminal`，于是按「给定路径中没有子模块」静默成功。故 `set -euo pipefail` **不会被触发，PR 构建不会因此失败**。

**4. 处理决定**

保留不动。理由：
- 无任何实际危害，它只是「什么也没做」
- 删除会造成与上游 diff，将来同步上游 `pr-check.yml` 时冲突
- 符合用户豁免原则：「不影响使用、无危险的遗留可保留，改了反而不知道会牵动什么」

### 教训

本条在初版交接文档中被写成「可能静默 no-op **或导致 PR 构建无故失败**」——后半句是**未经验证的推测**。实际动手复现后推翻。
