### 🔴 A. Media3 迁移 —— 风险最高

| 项 | 内容 |
|---|---|
| 提交 | `7137a1e` … `68576b7b`（共 11 条）+ `d06e7516`…`ca14b4be`（补 9 个漏改文件） |
| 改了什么 | ExoPlayer 2.19.1 → AndroidX Media3 1.11.1，13 个源文件 + 布局 |
| 涉及功能 | **音乐播放、背景视频、聊天里的音视频附件、Markdown 音视频渲染** |
| CI 状态 | ✅ 能编译能打包 |
| 真机状态 | ❌ **从没测过** |

**为什么必须验**：这是**纯 API 迁移**，CI 只保证「能编译」，**不保证播放行为不变**。
迁移清单里明确列了 3 个高风险点（报告自己写的）：

1. `PlayerView` 的 `findViewById` 返回类型转换 —— Media3 的 `PlayerView` 与旧 `StyledPlayerView` **层级不同**
2. `AspectRatioFrameLayout.RESIZE_MODE_*` 常量在 Media3 中是否同名同值
3. `app:keep_content_on_player_reset` 等自定义属性是否仍被 Media3 的 `attrs` 支持

**真机验证方法（手机可操作）**：

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 聊天里发一个**音频文件**（mp3） | 能播、有进度条、暂停/续播正常 |
| 2 | 聊天里发一个**视频文件**（mp4） | 能播、画面比例正常**不变形**、全屏正常 |
| 3 | 让 AI 用音乐工具放一首歌（`music_play`） | 能出声、能暂停、能调音量 |
| 4 | 设置 → 主题 → **背景** 选一个视频背景 | 背景动起来、**不是黑屏**、不卡顿 |
| 5 | Markdown 里嵌入音频/视频（让 AI 生成） | 渲染出来能播 |

> ⚠️ 第 4 项最关键 —— 报告自己说「背景视频播放属于聊天/主题功能，此项迁移正是为了保住它」。
> 如果 `keep_content_on_player_reset` 属性没被支持，**背景视频会直接黑屏**。
